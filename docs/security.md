# Безопасность и ограничения

[Все руководства](README.md) · [Эксплуатация](operations.md)

Инфраструктурный этап не является готовым сервисом обработки анкет. Пока нет
парсинга, профилей, контактов, аккаунтов, чёрных списков, жалоб, подписок,
Telegram, LLM, поиска уведомлений, доменной схемы БД и миграций. Нет HTTP API,
MCP, административного веб-интерфейса или интерактивного API explorer.
Карта компонентов — в [архитектуре](architecture.md).

## Секреты и диагностические данные

Строку подключения храните в переменной окружения либо игнорируемом локальном
файле; `.env` и `appsettings.Local.json` не должны попадать в коммит.
Публичный `.env.example` содержит заменяемые примеры. Пароль-заглушка Compose
предназначен для локальной воспроизводимости; задайте свой пароль.
`.codex/context/` публичен; личные настройки, prompt, PR body, кеши и состояние
инструментов остаются в игнорируемых каталогах.

[ConnectionStringDescriptor](../src/AnketaParser.Infrastructure/Configuration/ConnectionStringDescriptor.cs)
представляет адрес как `host:port/database`, без имени пользователя и пароля.
Валидаторы не повторяют сырую строку подключения. `DiagnosticsRunner` заменяет
текст исключения пробы именем типа; результат пробы PostgreSQL использует
классификацию ошибки. В JSON есть сведения о машине, процессе и адресе БД:
их также нужно просматривать перед публикацией.

Эти меры не гарантируют отсутствие секретов во всех логах: текущий
`PostgresReadinessProbe` передаёт объект исключения в `ILogger`, а общие
обработчики Host и CLI выводят `exception.Message`. Полный stderr перед
передачей другим людям нужно проверить и при необходимости обезличить.
Не выводите сырую конфигурацию и не считайте маскирование `target` фильтром
для всех исключений зависимостей.

## Контейнеры и данные

Основной Compose не публикует порты, но сеть `backend` не помечена `internal`:
это не обещание полной сетевой изоляции. Отладочный файл публикует PostgreSQL
только на loopback. Host запускается без root с `no-new-privileges`; это
не заменяет контроль доступа к Docker на машине.

[Dockerfile](../Dockerfile) копирует проектные файлы и `src/`, а
[.dockerignore](../.dockerignore) исключает локальные env и переопределения
из контекста сборки. Не помещайте секреты в произвольные файлы `src/`:
они могут попасть в контекст. Успех `SELECT 1` не подтверждает шифрование,
резервное копирование или корректность будущей доменной схемы.

Именованный том PostgreSQL хранит данные независимо от контейнера. Удаление
тома разрушает данные; безопасная остановка и предупреждение для
`down --volumes` находятся в [эксплуатации](operations.md). Изменение исходников
не разрешает перезапуск production, миграцию или удаление данных. Docker smoke
использует собственный стек и синтетическую БД, а не рабочий том.

Если обнаружен дефект обработки исключений или утечка, зафиксируйте место и
наблюдаемый эффект отдельно. Документация описывает существующее поведение;
менять runtime ради соответствия тексту нельзя.
