# Безопасность и ограничения

[Все руководства](README.md) · [Эксплуатация](operations.md)

Хранилище поддерживает анкеты, контакты, аккаунты, персональные списки, жалобы,
очередь и миграции. Это не готовый сервис сбора и публикации: парсер, Telegram,
LLM, подписки, уведомления, HTTP API и административный веб-интерфейс не реализованы.
Права, архивы и восстановление описаны в [регламенте хранения](persistence.md).
Карта компонентов — в [архитектуре](architecture.md).

## Секреты и диагностические данные

Строку подключения храните в переменной окружения либо игнорируемом локальном
файле; `.env` и `appsettings.Local.json` не должны попадать в коммит.
Публичный `.env.example` содержит заменяемые примеры. Пароль-заглушка Compose
предназначен для локальной воспроизводимости; задайте свой пароль.
`.codex/context/` публичен; личные настройки, промпты, описания PR, кеши и состояние
инструментов остаются в игнорируемых каталогах.

[ConnectionStringDescriptor](../src/AnketaParser.Infrastructure/Configuration/ConnectionStringDescriptor.cs)
представляет адрес как `host:port/database`, без имени пользователя и пароля.
Валидаторы не повторяют сырую строку подключения. `DiagnosticsRunner` заменяет
текст исключения пробы именем типа; результат пробы PostgreSQL использует
классификацию ошибки. В JSON есть сведения о машине, процессе и адресе БД:
их также нужно просматривать перед публикацией.

`PostgresReadinessProbe` записывает событие `2001` с безопасным адресом и категорией
отказа, без объекта исключения. Ошибки чтения JSON и привязки настроек заменяются
безопасными сообщениями без исходных значений. Общие обработчики Host и CLI
выводят только тип неожиданного исключения, без `Message`, стека и вложенных причин.
`ConnectionStringDescriptor.Redact` разбирает только строки подключения и не
предназначен для фильтрации произвольного текста исключения. Не выводите сырую
конфигурацию; сведения о машине и адресе БД проверяйте перед публикацией.

## GitHub Actions

Обычный CI исполняет код PR с `contents: read`, без дополнительных секретов;
checkout не сохраняет credentials. Линтеры работают в отдельном задании на тех же
непривилегированных событиях, включая PR из forks. Установка проверяет закреплённые
SHA256 официальных бинарных архивов до исполнения; zizmor не получает токен и
работает offline. Команды и ограничения проверки приведены в
[руководстве разработки](development.md).

В [доверенном workflow](../.github/workflows/pr-body-trusted.yml) намеренно
сохранён `pull_request_target`: он получает валидатор из точного
`github.event.pull_request.base.sha`, а не из head. Единственное inline-исключение
`dangerous-triggers` относится к этому событию: checkout не сохраняет учётные
данные, права доступа ограничены `contents: read` и `pull-requests: read`, номер PR
поступает через `env`, команда запуска литеральна. Python-модули валидатора берутся
из base; подмена модулей head проверяется регрессионным тестом
[test_trusted_pr_validation.py](../.github/scripts/test_trusted_pr_validation.py).
Исключение требует повторной оценки при изменении ref, команды, импортов,
окружения или прав доступа. Оно не распространяется на другие workflow или правила.

Кандидатная проверка `pull_request` исполняет код PR и не обеспечивает
независимого контроля. Статический аудит не заменяет проверку границ доверия и
не защищает от всех изменений workflow, которые может предложить автор PR.
Настройка обязательных проверок выполняется отдельно после проверки реально
активных контекстов.

## Анализ контейнеров и исходного кода

[Проверка контейнеров](../.github/workflows/container-security.yml) запускается на
PR, `main`, `merge_group`, вручную и еженедельно. Hadolint проверяет отслеживаемые
Dockerfile и Containerfile; пустой список и ошибка анализатора недопустимы. Версии
Hadolint и Trivy и SHA256 архивов закреплены в workflow. Точечные исключения
Hadolint в Dockerfile относятся к версиям APT/APK и UID базового образа; причины и
условия пересмотра указаны рядом с инструкциями. Это не воспроизводимый снимок
пакетов: обновления в репозиториях дистрибутивов могут изменить результат сборки.

Trivy отдельно проверяет Dockerfile и контейнерные образы. Стандартные проверки
Trivy [не поддерживают Compose](https://trivy.dev/docs/latest/coverage/iac/docker/),
поэтому оба исходных Compose-файла и итоговые модели обычного и отладочного
вариантов со всеми профилями разбираются как YAML с ограниченной
[пользовательской политикой](../.github/security/compose.rego). Она проверяет
`privileged`, перечисленные в политике пространства имён хоста и монтирование
сокета Docker, но не является полным аудитом Compose. Отдельные негативные
контроли проверяют каждый запрет, интерполяцию и объединение файлов. Неопознанный
файл или пустой отчёт не считается успехом. Развёрнутые модели в лог не выводятся.

Проверка образов без кеша собирает Host, maintenance и PostgreSQL по Compose,
не создавая сервисы, сети и тома. Модели со всеми профилями, в том числе с
отладочным файлом, сверяются с набором проверяемых образов и сборок: общий образ
maintenance и backup анализируется один раз, неизвестный образ или
неоднозначная сборка блокируют задание. Для каждого образа
сверяются имя, локальный ID, тип и ОС в отчёте, наличие пакетов ОС и ожидаемых
библиотек .NET и Go; выводятся обнаруженные CVE, статус и версия исправления.
Все обнаруженные HIGH и CRITICAL блокируют проверку, включая находки без
исправления: наличие пакета само по себе не доказывает эксплуатируемость, а
отсутствие исправления не устраняет риск. Требуется ручной разбор применимости,
обновление или адресное обоснованное решение, а не общее скрытие `unfixed`.
Отсутствие образа, базы или корректного отчёта — ошибка инфраструктуры. При каждом
запуске база загружается в новый временный кеш и сканирование повторяется.
Метки UTC сверяются с `NextUpdate`: допускаются сутки задержки после него и пять
минут расхождения часов; противоречивые или устаревшие метаданные блокируют
проверку. Отчёты и образы не публикуются в сторонний реестр. Это не анализ всех
рисков сборочной цепочки, доступности исправлений и будущих CVE.

Образы Host обновляют APT-пакеты, а общая стадия PostgreSQL — установленные
APK-пакеты. До обновления `gosu` в официальном PostgreSQL он пересобирается из
закреплённой ревизии исходников в отдельной стадии с закреплённым образом Go;
компилятор в исполняемые образы не переносится. Сборка требует доступа к Go
module proxy и базе контрольных сумм. При обновлении базового PostgreSQL следует
проверить встроенный `gosu` и возможность убрать эту стадию. Чтобы получить свежие
пакеты вне CI, пересобирайте образы без кеша; существующие образы автоматически
не обновляются. Замена образа не разрешает перезапуск рабочей БД или удаление томов.

[CodeQL Advanced](../.github/workflows/codeql.yml) разделяет C# и Python на
независимые задания с `security-extended`. C# анализируется при ручной сборке
решения с `--locked-mode`; Python — без сборки с явным выбором `.github/scripts`.
Оба задания выводят состав архива исходников базы и сверяют его с отслеживаемыми
файлами; выгрузка результатов ожидает обработки Code Scanning. Фактический охват,
завершение запросов и публикацию необходимо подтверждать для конкретного запуска,
а не по наличию файла workflow. [CodeQL документирует .NET 10 и Python до 3.14](https://codeql.github.com/docs/codeql-overview/supported-languages-and-frameworks/):
для экстрактора выбран Python 3.14, но это не доказывает поддержку синтаксиса и
семантики Python 3.15, на котором работает основной CI. Для PR из forks действуют
ограничения GitHub на токен и загрузку SARIF; отказ публикации не означает успеха.
Advanced Setup требует отключённого Default Setup: при изменении настроек владельцем
нужно заново проверить режим и выгрузку. Checkout не сохраняет credentials;
разрешение `security-events: write` ограничено заданиями CodeQL, дополнительные
секреты, `pull_request_target` и привилегированные self-hosted runners не нужны.

## Контейнеры и данные

Основной Compose не публикует порты, но сеть `backend` не помечена `internal`:
это не обещание полной сетевой изоляции. Отладочный файл публикует PostgreSQL
только на петлевом интерфейсе. Host запускается без root с `no-new-privileges`; это
не заменяет контроль доступа к Docker на машине.

[Dockerfile](../Dockerfile) копирует проектные файлы и `src/`, а
[.dockerignore](../.dockerignore) исключает локальные файлы окружения и переопределения
из контекста сборки на любой глубине (`**/.env`, `**/.env.*`,
`**/appsettings.Local.json`). Не помещайте секреты в произвольные файлы `src/`:
они могут попасть в контекст. Успех `SELECT 1` не подтверждает шифрование,
резервное копирование или корректность прикладных данных.

Именованный том PostgreSQL хранит данные независимо от контейнера. Удаление
тома разрушает данные; безопасная остановка и предупреждение для
`down --volumes` находятся в [эксплуатации](operations.md). Изменение исходников
не разрешает перезапуск рабочей среды, миграцию или удаление данных. Проверка Docker
использует собственный стек и синтетическую БД, а не рабочий том.

Если обнаружен дефект обработки исключений или утечка, зафиксируйте место и
наблюдаемый эффект отдельно. Документация описывает существующее поведение;
менять исполняемый код ради соответствия тексту нельзя.
