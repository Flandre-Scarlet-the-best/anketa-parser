# Запуск и эксплуатация

[Все руководства](README.md) · [Конфигурация](configuration.md) · [Диагностика](diagnostics.md)

Выберите локальный процесс для проверки инфраструктуры без БД или Compose для
совместного запуска Host и PostgreSQL. Сначала установите зависимости из
[руководства разработчика](development.md).

Подключение треда, расписание и расшифровка статусов описаны в
[руководстве сбора Двача](dvach.md).

## Локальный процесс

После восстановления зависимостей из корня репозитория:

```sh
dotnet run --project src/AnketaParser.Host
```

Процесс остаётся работать до `Ctrl+C`; в Linux/WSL также поддерживается SIGTERM.
Без настроенной БД начальная проверка даёт деградацию, монитор сообщает, что
зависимость не настроена, и не запускает пустой цикл. Это нормальный локальный
режим, который не подтверждает соединение с PostgreSQL.

Для диагностики из другого терминала:

```sh
dotnet run --project src/AnketaParser.Cli -- doctor --json
```

CLI проверяет собственное окружение и конфигурацию, а не опрашивает запущенный
Host. Передавайте одинаковые настройки окружения для сопоставимых результатов.
Параметры из каталога сборки Host автоматически в CLI не переходят.

## Host и PostgreSQL в Docker

Нужны работающий Docker Engine / Docker Desktop и Compose v2.
Скопируйте публичный пример, **если `.env` ещё не существует**, сохранив свои
локальные значения. В PowerShell:

```powershell
Copy-Item .env.example .env
```

В Bash/WSL:

```bash
cp .env.example .env
```

Откройте `.env` и задайте свои пароли PostgreSQL и трёх служебных ролей.
Выполните [первичную подготовку БД и миграции](persistence.md#новая-бд-и-переход-существующей-установки)
перед первым запуском Host или переходом существующей установки. Затем:

```sh
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 600
docker compose ps
docker compose logs -f host
```

`config --quiet` проверяет только описание; `up --wait` ожидает состояния
контейнеров. PostgreSQL собирается локально: `pull_policy: never` не загружает
локальный образ PostgreSQL из реестра; `--build` обновляет его при запуске команды
выше. Сборка не изменяет существующую базу и сама по себе не перезапускает
контейнеры. Ожидайте `healthy` у `postgres` и `host`. `Ctrl+C` при просмотре логов
прекращает просмотр, а контейнеры продолжают работать.

Конфигурацию определяют [compose.yaml](../compose.yaml) и [Dockerfile](../Dockerfile):

| Объект | Поведение |
| --- | --- |
| `postgres` | Локальная сборка на основе `postgres:18.6-alpine` с обновлёнными пакетами и `gosu`; том `postgres-data` в `/var/lib/postgresql`; `pg_isready` каждые 5 секунд, таймаут 5 секунд, 20 попыток, начальный период 10 секунд |
| `host` | Сборка SDK → среда выполнения с восстановлением `--locked-mode`, пользователь `APP_UID`, `no-new-privileges`, `init: true`; старт после здоровой PostgreSQL |
| Проверка Host | Новый CLI `doctor --json` каждые 30 секунд, таймаут 15 секунд, 3 попытки, начальный период 20 секунд |
| Сеть `backend` | Общая сеть без публикации портов; отдельной изоляции исходящего трафика `internal: true` нет |
| Перезапуск | `restart: unless-stopped`; остановка Host получает 30 секунд |

`pg_isready` проверяет доступность сервера; проба Host дополнительно открывает
соединение с учётными данными, выполняет `SELECT 1` и проверяет версию миграций. Готовая PostgreSQL ещё
не доказывает, что приложение подключится. Код `4` CLI означает неуспешную
проверку; после заданного числа отказов Docker отмечает контейнер `unhealthy`.
Сам healthcheck контейнер не перезапускает.

Прямой диагностический вызов внутри контейнера:

```sh
docker compose exec -T host dotnet /app/cli/AnketaParser.Cli.dll doctor --json
```

При штатной БД проба `postgres` имеет статус `healthy` и код `0`.
Проба `backup` даёт общую деградацию до свежей проверки копии восстановлением.

### Переменные Compose

`.env` интерполируется Compose и не загружается самим приложением.

| Переменная | Если не задана | Назначение |
| --- | --- | --- |
| `POSTGRES_DB` / `POSTGRES_USER` | `anketa_parser` / `anketa_parser` | Начальная БД и пользователь |
| `POSTGRES_PASSWORD` | `local-development-password` | Локальная заглушка; задайте свой пароль |
| `DOTNET_ENVIRONMENT` | `Production` | Окружение Host и контейнерного CLI |
| `ANKETAPARSER_INSTANCE_NAME` | `anketa-parser` | Передаётся как `ANKETAPARSER_Host__InstanceName` |
| `ANKETAPARSER_DB_DEBUG_PORT` | `55432` | Только отладочный файл |

Compose передаёт строку подключения к `postgres:5432`, обязательность БД,
таймаут остановки 20 секунд и JSON-формат логов. Произвольная `ANKETAPARSER_`
переменная терминала не попадает в контейнер автоматически: действует явная
секция `environment`.

Смена `POSTGRES_PASSWORD` в `.env` не меняет пароль уже инициализированной БД
в сохранённом томе. Восстановите правильную настройку; не удаляйте том ради
устранения ошибки входа.

### Доступ к БД для отладки

По умолчанию ни один порт не публикуется. Для явного доступа с этой машины:

```sh
docker compose -f compose.yaml -f compose.debug.yaml up -d postgres
psql "host=127.0.0.1 port=55432 dbname=anketa_parser user=anketa_parser"
```

Нужен отдельно установленный `psql`; пароль вводится по запросу. Если меняли
БД, пользователя или порт в `.env`, подставьте свои значения.
[compose.debug.yaml](../compose.debug.yaml) публикует только `127.0.0.1:55432`.
Остановить этот сервис можно той же комбинацией файлов:

```sh
docker compose -f compose.yaml -f compose.debug.yaml stop postgres
```

Для SQL без публикации порта используйте читающий запрос внутри контейнера
(при стандартных имени пользователя и БД):

```sh
docker compose exec -T postgres psql -U anketa_parser -d anketa_parser -tAc "SELECT 1"
```

Ожидайте `1`. Таблица `smoke_marker` создаётся только изолированным тестом;
её нет в обычном стеке приложения.

## Штатная остановка и данные

`Ctrl+C` / SIGTERM запускают штатную остановку локального Host. В контейнере:

```sh
docker compose stop
docker compose down
```

`stop` останавливает сервисы, `down` удаляет контейнеры и сеть проекта,
сохраняя именованный том. Используйте команды только для своего проекта;
параметр `-p` при создании стека меняет его имя и должен сохраняться при управлении.
Host ожидает завершения фоновой работы в пределах `Host:ShutdownTimeoutSeconds`;
Compose даёт 30 секунд до принудительной остановки контейнера. При работающем
мониторе событие `3006` отмечает завершение. Штатный выход Host — `0`.

**Разрушительная команда:** `docker compose down --volumes` удаляет в том числе
том PostgreSQL вместе со всеми данными этого проекта. Для обычного выключения
она не нужна. Не выполняйте её для проверки текста или исправления непонятной ошибки.

## Окна консоли на Windows

Приложение запускает дочерние процессы без окна консоли: утилиты `pg_dump` и
`pg_restore` в операциях [резервного копирования и восстановления](persistence.md)
и тестовый хелпер, запускающий собранное приложение, получают параметры запуска с
`CreateNoWindow` и перенаправленными потоками. Вывод утилит отбрасывается,
а диагностика сообщает об отказе без исходного текста. Окно, которое иногда появляется при `dotnet test`, создаёт сам
инструмент запуска тестов, а не код продукта: это поведение средства проверки, и
переписывать тестовый хост для него не требуется.

## Если запуск не удался

| Наблюдение | Что проверить |
| --- | --- |
| SDK несовместим | `global.json`, `dotnet --version`; [требования](development.md) |
| Host завершился с `3` | stderr, диапазоны и источники [конфигурации](configuration.md) |
| Host не стартовал с `4` | `docker compose ps`, `docker compose logs postgres`, адрес и учётные данные |
| CLI вернул `4`, а Host работает | Необязательная настроенная БД также даёт `4` у CLI; [семантика](diagnostics.md) |
| Нет соединения с `localhost` | Основной Compose порт не публикует; используйте `exec` либо отладочный файл |
| Ошибка пароля после изменения `.env` | В томе остаются прежние учётные данные; восстановите соответствующие значения |
| Ошибка `POSTGRES_PASSWORD` при изменённом Compose | Сверьте описание и `.env`; текущий Compose содержит заглушку и не требует `.env` синтаксически |
| `libgssapi_krb5.so.2` в логах старого образа | В текущем Dockerfile есть `libgssapi-krb5-2`; пересоберите свой образ |
| Docker-тест пропущен | Он включается отдельно; [разработка и проверки](development.md) |

Не публикуйте полный вывод конфигурации и логи без просмотра: они могут содержать
локальные адреса или сведения исключений. [Секреты и логи](security.md).
